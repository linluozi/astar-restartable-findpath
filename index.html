A* that can change its mind

Upstream closes every expanded node forever and rebuilds the whole candidate path on every relaxation. The first habit returns a sub-optimal path whenever the heuristic is admissible but not consistent; the second makes a single search copy 4.7 million nodes. One rewrite fixes both.

01 — DEFECT

The closed set is a lie for inconsistent heuristics

A* may return early — and may refuse to re-open a node — only if the heuristic is consistent, i.e. h(u) ≤ cost(u,v) + h(v) for every edge. The package documentation never says that. Both of its examples pass the same function as cost and as heuristic, which is admissible but not necessarily consistent.

With an inconsistent heuristic, queue order stops being cost order. The destination pops before a cheaper route has reached it, and a node that is later reached more cheaply is discarded at the top of the loop.

02 — CHANGE

Carry g, keep one entry per node, allow re-opening

  1. The path is never rebuilt during the search. Each queue entry stores the cost g it arrived with, so priority is g + h — one call to h per improving relaxation, not one per edge of a copied path.
  2. One open-set entry per node. An improved node has its key lowered in place with heap.Fix; a node that has already been popped is pushed again. There are no stale duplicates to skip.
  3. Re-opening is allowed. Combined with “return only when the destination is popped with its final g”, the result is optimal for every admissible heuristic, consistent or not. The path is reconstructed once, at the end, from a predecessor table.

Timings from two 9-round sessions plus three shorter runs; the range spans all five, because the same case moved 3.43× → 2.46× between sessions on an unchanged binary. The last two columns are deterministic counters and do not move at all between runs.

Why the counters are the stronger evidence. Timing on one machine drifts by tens of percent. d-call counts do not: they follow a closed form that both arms reproduce bit for bit, and the two arms expand exactly the same number of nodes on every consistent-heuristic workload — 599, 299, 248, 164, 631. The patch does not search less; it stops re-walking paths it has already costed.

Not proven: the Linux CI job was never executed on a Linux kernel — no container runtime on this machine, so only compilation, vetting and test compilation were reproduced for GOOS=linux. Peak memory is a Windows measurement (psapi.dll). And on ties the patched version may return a different, equally optimal path than upstream; the cost is what is guaranteed, not the node sequence.
